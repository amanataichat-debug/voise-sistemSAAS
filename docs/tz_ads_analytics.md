## 1. Зачем

Клиенты владельца (например, бизнес в Казахстане) запускают рекламу в рекламном кабинете
Meta. Люди видят объявление в Instagram / Facebook, нажимают кнопку и пишут в Instagram
Direct, WhatsApp или Telegram. Дальше с ними переписывается наш агент, клиент проходит по
воронке, часть покупает.

Сейчас эта цепочка рвётся: рекламный кабинет знает, сколько потрачено и сколько было
кликов, а наша система знает переписку и стадию клиента, но не знает, из какой рекламы он
пришёл. Нужно соединить:

**реклама (бюджет, показы, клики) → кто написал → что ответил агент → стадия → продажа и сумма**

и показывать это в кабинете: сколько стоил каждый клиент, какая реклама приводит продажи,
а какая — только пустые переписки.

## 2. Что есть в системе сейчас

- Каналы переписки агента: WhatsApp (Evolution API, неофициальное подключение по QR,
  `services/whatsapp_inbound.py`), личный Telegram (Telethon, поллер
  `core/telegram_user_poller.py`), Instagram Direct (Composio, поллер
  `core/instagram_poller.py`). Подробно — CLAUDE.md.
- Контакт — `agent_contacts` (имя, телефон, стадия `status`, память `memory`). **Поля
  «источник / реклама» нет.** Поля «сумма сделки» нет.
- Воронка — 5 стадий (`backend/core/pipeline_stages.py`): Новый, В работе, Успех, Отказ,
  Не звонить. Канбан — `static/agent/pipeline.js`.
- Переписка по каналам — `agent_whatsapp_messages`, `agent_telegram_messages`,
  `agent_instagram_messages`; первое сообщение клиента там есть.
- С рекламным кабинетом Meta система не связана никак.

## 3. Как узнать, из какой рекламы пришёл клиент (атрибуция)

Варианты по надёжности. Возможности API помечены «проверить» — это гипотезы, их надо
подтвердить в первой сессии (раздел 5) по документации Meta и на тестовом объявлении.

1. **Данные объявления в самом сообщении (лучший вариант, если доступен).**
   - Объявления «Click to WhatsApp» и «Click to Instagram Direct» передают с первым
     сообщением сведения о рекламе (id объявления, заголовок, ссылка) — в официальном
     WhatsApp Cloud API это поле `referral`, в Instagram Messaging webhook — `referral`
     с `ad_id`. **Проверить:** отдаёт ли это Evolution API / Baileys (у нас неофициальный
     WhatsApp; в протоколе WhatsApp Web это может быть `contextInfo.externalAdReply` /
     `ctwaContext`) и отдаёт ли Composio-тулкит Instagram при опросе сообщений (скорее
     нет — тогда нужен свой Meta-апп с вебхуком Instagram Messaging).
2. **Метка в заготовленном тексте первого сообщения.** У каждой кампании своя ссылка с
   заготовленным текстом: `wa.me/<номер>?text=Здравствуйте!%20(код%20KZ-A12)`, для
   Instagram — свой текст-заготовка в объявлении. Система находит код в первом
   сообщении и привязывает клиента к кампании. Работает в любом канале, но клиент может
   стереть код.
3. **Ссылки для Telegram.** У личного аккаунта нет параметра `start`, поэтому только
   вариант 2 (заготовленный текст) или отдельный Telegram-бот (`t.me/bot?start=A12` —
   надёжно, но это другой канал, не личный аккаунт).
4. **Совпадение по времени (резерв).** Клиент написал впервые, пока шла кампания на этот
   канал, — помечать «вероятно из рекламы X» (с пометкой «примерно»).
5. **Ручная метка.** Владелец или агент ставит источник в карточке клиента
   (например, «пришёл по рекомендации»).

## 4. Что показывать (метрики) — предложение для согласования

### 4.1 Деньги и реклама (из рекламного кабинета Meta)
- расход, показы, охват, частота, клики, CTR, CPC, CPM — по кампании / группе / объявлению;
- «начатые переписки» по данным Meta и стоимость одной переписки;
- валюта кабинета (для Казахстана — KZT), пересчёт в валюту отчёта.

### 4.2 Воронка (наши данные)
- написали → агент ответил → в работе → успех / отказ, по каждому объявлению и каналу;
- конверсия между этапами, где «застревают» клиенты;
- **стоимость лида (CPL)** = расход / написавшие; **стоимость продажи (CAC)** = расход / успех;
- **ROAS / окупаемость** = выручка / расход — требует суммы сделки (см. 6.4).

### 4.3 Качество работы агента (наше преимущество — этого нет в рекламном кабинете)
- время первого ответа агента; доля клиентов, которым ответили за 5 минут;
- доля переписок, где владелец перехватил клиента (пауза `owner_message`);
- «потерянные» клиенты: написали, но не ответили на последнее сообщение агента 24 / 72 часа;
- причины отказа (из памяти контакта `memory`) — сводка по объявлениям: «дорого», «не тот
  размер», «просто спросить»;
- голосовые vs текст: где больше доходят до успеха;
- тепловая карта «когда пишут» (день недели × час) — когда держать агента активнее.

### 4.4 ИИ-сводка (наше преимущество)
- раз в неделю оркестратор пишет владельцу в Telegram-бот: «объявление A — 12 продаж по
  3 400 ₸, объявление B — 40 переписок, 0 продаж, клиенты спрашивают цену и уходят —
  предлагаю отключить B»;
- тревога: стоимость лида выросла на 50 % за 3 дня;
- вопрос в чате агента: «какая реклама лучше на этой неделе?» — ответ по данным.

### 4.5 Обратная отправка в Meta (сильное преимущество, этап 3)
- Conversions API: отправлять в Meta события «лид квалифицирован» и «покупка» по
  клиентам из рекламы — Meta начинает оптимизировать показы под тех, кто реально покупает,
  а не просто пишет. **Проверить** требования к данным и доступ для сообщений из мессенджеров.

## 5. Что проверить в первой сессии, до кода

1. Доступ к рекламному кабинету Meta: Marketing API (Insights), нужное разрешение
   (`ads_read`), понадобится ли проверка приложения Meta (App Review) и верификация
   бизнеса; сроки. Альтернатива: есть ли у Composio тулкит Meta Ads / Facebook Ads
   (у нас уже есть Composio для Instagram) — это может сэкономить App Review.
2. Подключение рекламного кабинета клиента платформы: вход через Facebook (OAuth) из
   нашего кабинета, выбор рекламного аккаунта. Хранение токена, обновление.
3. Атрибуция в WhatsApp через Evolution: приходит ли в webhook `messages.upsert`
   информация о рекламе (сделать тестовое объявление Click-to-WhatsApp на маленький
   бюджет и посмотреть сырой payload в логах `[WA-IN]`).
4. Атрибуция в Instagram: есть ли `referral` / `ad_id` в ответе Composio
   `INSTAGRAM_LIST_ALL_MESSAGES`; если нет — нужен ли свой Meta-апп с webhook Instagram
   Messaging и что это меняет.
5. Лимиты и задержка Insights API (данные за сегодня обновляются с задержкой; сколько
   запросов можно делать).
6. Валюты: KZT / KGS / USD — откуда брать курс (в кошельке уже есть `WALLET_KGS_USD_RATE`).

Итог первой сессии — короткий отчёт владельцу простым языком: что точно получится,
что нет, что требует действий от него (например, создать приложение в Meta for Developers,
пройти проверку бизнеса), и уточнённый план этапов.

## 8. Проверка перед словом «готово»

- Локальная Postgres (`/usr/lib/postgresql/16/bin`, SSL), `create_all`, затем DROP новых
  колонок, запуск `uvicorn app:app` с `PRODUCTION=true` — колонки создались, страницы и
  API без 500.
- Сквозные тесты на настоящих строках БД, подменяется только сеть (Meta API, Evolution,
  Composio): клиент из рекламы → источник записан → стадии → отчёт считает верно.
- UI — в браузере (Playwright, Chromium в `/opt/pw-browsers`), скриншоты владельцу.
- Честно разделять проверенное локально и то, что покажет только тест с настоящим
  рекламным кабинетом и объявлением.
