# Полный аудит платформы Voksy AI и план «чистой системы» — 11.11.2026

Ветка `1111-clean-system`. Аудит с нуля, по коду (базы прода не видно). Первая часть аудита —
`docs/audit_2026_11_11.md`, здесь она не повторяется, а сведена в общий список.

Обозначения: **P0** — ломает работу или теряет клиентов/деньги, чинить первым; **P1** — портит качество
ответа или звонка; **P2** — порядок, скорость, чистота. «Где» — файл, где исправлять.

## 1. Как система работает сейчас (карта)

```
Сайт (React, prerender) → регистрация → кабинет (vanilla HTML) → тариф (Finik) → агент
                                                                      │
   ┌──────────── ПЕРЕПИСКА ─────────────┐        ┌──────────── ЗВОНОК ───────────────┐
   WhatsApp: шлюз Evolution → webhook   │        Asterisk (VPS) → bridge.py → /ws/sip/{id}
   Telegram: поллер раз в 60 с          │        → промпт звонка = карточка + знания + контекст
   Instagram: поллер раз в 90 с         │        → движок: GPT-Live | Gemini Live | Voksy Voice
        ↓ (задержка 15 с, склейка серии)│        → запись MP3 в R2, стенограмма
   PostCall-оркестратор (OpenRouter LLM)│        → AgentCallFinalizer → PostCall-оркестратор
   + ~35 инструментов → ответ, CRM      │             (разбор звонка, CRM, задачи, материалы)
   └────────────────────────────────────┘        └───────────────────────────────────┘
                       ↓                                      ↓
   CRM: agent_contacts (карточка, memory, этапы) · tasks (звонки, напоминания) · воронка (sales_funnel)
   Планировщик задач (каждые 30 с) → PreCall (первая фраза) → исходящий звонок
```

Промпт сейчас складывается из слоёв: код (ядро оркестратора 10,8 тыс. символов, правила событий, «сознание»
переписки, режим тарифа) + 5 документов владельца + доп. инструкции (шаблон Анри ~25 тыс.) + знания до 10 тыс.
Звонок: код-подсказки голоса 11–15 тыс. + карточка (замороженная в БД) + знания 9 тыс. + контекст звонка.

## 2. P0 — ломает работу (чинить первым)

| № | Что | Почему плохо | Где |

## 7. Целевая система (как должно быть)

**Три слоя, у каждого своя работа, слои не спорят:**

1. **Код = механика и безопасность.** Захват задач, очередь на клиента, подметание неотвеченных, время,
   окно звонков и антиспам, лимиты WhatsApp, пауза, чистка текста, проверки перед отправкой (повтор вопроса,
   «удобно ли?» после согласия), запись в CRM, оповещение владельцу о сбоях. Модель это не «помнит» — код делает.
2. **Общий системный промпт (один на платформу)** — коротко, без «главнее», по одному месту на правило:
   - переписка: ядро (данные — из инструментов, факты — из базы, язык собеседника) + блок «клиент» (формат 1–3 строки,
     один вопрос максимум, «---» для второго сообщения, сайт/номер из настроек, ответ первым, CRM после) или
     блок «владелец» (справочник инструментов);
   - звонок: ОДИН модуль правил голоса для всех трёх движков (≤ 6 тыс.: манера, длина реплики, вопросы,
     перебивания, «подумаю», язык, завершение, материалы) + кыргызский блок по-кыргызски + маленькая добавка движка
     (GPT-Live — делегирование бэкенду, Gemini/Voksy Voice — когда звать функции).
3. **Платформа (заполняет владелец, без кода):**
   - «Инструкция для переписки» — персона, продукт, сценарий продаж;
   - «Инструкция для звонков» — та же персона голосом, сценарий звонка;
   - База знаний — цены, условия, вопрос-ответ, каталог, файлы;
   - Контакты компании — сайт и номер для звонка (одно поле, читают и переписка, и звонок);
   - Голос и движок, номер телефонии, каналы.

Шаблоны владельца (`docs/*_anri.md`) — только персона/продукт/сценарий, без журналов правок и без правил,
которые уже держит код.

## 8. План работ (порядок исполнения; после каждого шага — тесты и проверка импорта)

1. **P0 механика:** атомарный захват задач (0.1); очередь на клиента + подметание неотвеченных чатов (0.2, 0.3);
   кредиты/подписка → владельцу оповещение, строка не висит (0.4, 2.7); проверка ответа (0.5).
2. **Переписка:** новый промпт (ядро + клиент/владелец) (1.2–1.9), нарезка (1.1), контакты компании из настроек
   (1.4), убрать `send_sms`/`check_phone_operator` из набора разбора (0.8, 1.9), язык PreCall (1.11), параллельные
   разборы в поллерах (1.10).
3. **CRM:** память контакта (2.1–2.3), заметки (2.4), шаг «имя/компания» (2.5), описания задач (2.6).
4. **Голос:** общий модуль правил для трёх движков (3.1–3.4, 3.7), кыргызский блок (3.5), язык начала (3.6),
   промпт звонка собирается из кода на каждом звонке (0.6), факты Voksy убрать из кода (0.7).
5. **Шаблоны владельца** (`docs/orchestrator_prompt_anri.md`, `docs/voice_agent_prompt_anri.md`) и
   **инструкция подключения** (`docs/onboarding_new_client.md`).
6. **Тесты** на поведение (без sha256 и без зависимости от часа) + `CLAUDE.md` / `claude-*.md`.
7. **Мёртвый код** (4.1, 4.2) — только то, что не импортируется живым кодом; приложение должно стартовать.
