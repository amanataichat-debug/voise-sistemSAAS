# ТЗ ветки `2110-client-memory`: без дублей звонков + агент узнаёт клиента

Ветка `2110-client-memory` ответвлена от `1910-voice-fix-test1` (коммит `da3681b`,
там уже есть настройка «Окно звонков» в разделе «Звонки»). Работаем, коммитим и
пушим только сюда. Pull request не создаём. Прод (Render) пока на
`1910-voice-fix-test1` — эту ветку владелец выкатит сам после теста.

Три задачи, по порядку: 1 — быстрая, 2 и 3 — объёмнее.

## Что НЕ трогаем

- Логику «не долбить клиента» в целом (сколько звонков, когда «Не звонить») —
  её делает отдельный разработчик. Поведение задаёт промпт оркестратора владельца
  (раздел «Правила и цели» инструкций агента): 1 звонок → сообщение в
  мессенджер → 1 повтор завтра → «Не звонить»; клиент вышел на связь — счётчик 0.
  Наша задача 1 — только защита от дублей задач, без новой политики.
- Шлюз на VPS (`infra/sip-gateway/`) — не меняем.
- Voximplant — мёртвый код, не трогаем (см. CLAUDE.md).

## Задача 1. Защита от дублей задач на звонок

### Что случилось на живом тесте 21.10.2026

Клиент 0507103503 не взял трубку. Оркестратор в PostCall написал ему в WhatsApp
(правильно) и поставил задачи на звонок — две: 22.10 14:37 (правильная, «завтра»)
и 21.10 14:38 (ошибочная, через ~3 минуты). Удалить ошибочную он не смог и
попросил владельца сделать это руками. Без удаления клиенту позвонили бы второй
раз в тот же день (около 17:38: кулдаун 3 ч в `TaskScheduler._dial_gate` задачу
не отменяет, а только переносит).

### Причины (по коду `1910-voice-fix-test1`)

1. `agent_tools.fn_create_agent_task`: если `scheduled_at` в прошлом (модель
   ошиблась со временем / часовым поясом), задача молча ставится на «сейчас +
   3 мин» (`clamped to …`), а не отклоняется.
2. `_check_call_guards` проверяет «сегодня уже звонили» по
   `AgentContact.last_called_at`. Это поле PostCall записывает в КОНЦЕ анализа
   (`agent_orchestrator._analyze_v3_openrouter`), то есть пока модель разбирает
   недозвон, проверка видит вчерашнюю дату и пропускает звонок на сегодня.
3. Задач на звонок у одного клиента может быть сколько угодно (отменяются только
   дубли с точно тем же временем).
4. В PostCall у модели нет `delete_agent_task` / `get_agent_tasks` (они есть
   только в чате с владельцем, `AGENT_CHAT_TOOLS`).

### Что сделать

- **«Сегодня уже звонили» — по факту.** В `_check_call_guards` (или рядом) кроме
  `last_called_at` смотреть реальные исходящие звонки этому клиенту за сегодняшний
  день по Бишкеку: строки `sip_calls` (direction=outbound, `to_number` = номер
  контакта, нормализованный `normalize_sip_number`, `created_at` ≥ начало дня по
  Бишкеку). Был сегодня исходящий — новый звонок на сегодня не ставится, отказ с
  понятным hint («сегодня уже звонили, ближайший — завтра в окно звонков»).
  Касается `create_agent_task(channel="call")` и `trigger_immediate_call`.
- **Время в прошлом — для звонка не «через 3 минуты».** Для `channel="call"`
  после недавнего звонка клэмп «сейчас + 3 мин» не должен обходить проверку выше
  (проверка идёт уже по итоговому времени). Отдельно решить: возвращать ли модели
  отказ «время в прошлом, пересчитай» вместо тихого клэмпа.
- **Одна запланированная задача на звонок у клиента.** Новая задача на звонок
  отменяет прежние SCHEDULED-задачи на звонок этого же контакта (новая — последнее
  решение агента). В ответе тулзы — что заменили («звонок на 22.10 14:37 заменил
  звонок на 21.10 14:38»). Telegram-задачи (`channel="telegram"`) и напоминания
  владельцу (`channel="owner"`) не трогать.
- Логировать каждую отмену/отказ (`[AGENT-TOOLS] …`), чтобы владелец видел причину
  в истории агента.

### Готово, когда

- [ ] Недозвон → оркестратор не может поставить звонок на сегодня (ни
      `create_agent_task`, ни `trigger_immediate_call`), даже если передал время в
      прошлом.
- [ ] Вторая задача на звонок тому же клиенту заменяет первую, в «Ближайших
      задачах» всегда одна.
- [ ] Ручной звонок со страницы «Телефония» работает как раньше.

## Задача 2. Агент узнаёт клиента по имени, нише, компании, номеру

### Как сейчас (проверено по коду)

- Входящий с **того же номера** — работает (Этап 3,
  `SipGatewayService.inbound_known_contact_block`): контакт агента ищется по
  последним 9 цифрам, в промпт звонка идут имя, ниша, запрос, summary, удобное
  время и последние 10 событий единой хронологии (`agent_orchestrator.build_conversation_timeline`:
  звонки + WhatsApp + Telegram + Instagram).
- Входящий с **другого номера** — `SipGatewayService.inbound_recent_contacts_hint`
  (Этап 10): в промпт идёт список до 5 контактов, обновлённых **за последний час**,
  только «имя (ниша)». Агент спрашивает имя и сопоставляет.
  Проблемы:
  - окно 1 час: клиент, писавший вчера, в список не попадёт;
  - подсказка велит искать через `search_contact_by_phone` «по прежнему номеру из
    списка», но номеров в списке нет;
  - `search_contact_by_phone` (`backend/functions/search_contact_by_phone.py`)
    ищет в старой CRM (`contacts` + голосовые диалоги), а не в контактах агента
    (`agent_contacts`) и не в переписках мессенджеров;
  - поиска по имени / нише / компании на звонке нет вообще.
- Список подмешивается ВСЕГДА при незнакомом номере — независимо от того, писал ли
  клиент «позвоню с другого номера». Отдельного «поиска по слову клиента» нет.

### Что сделать

- **Голосовая функция поиска клиента** (новый модуль в `backend/functions/`,
  например `find_client.py`, по образцу `search_knowledge_base.py`): ищет по
  `agent_contacts` ЭТОГО агента по имени, компании, нише (`memory.niche` /
  `industry`), номеру (в т.ч. старому / второму номеру, см. задачу 3). Возвращает
  1–3 лучших совпадения: имя, компания, ниша, запрос, summary, последние 5–10
  событий хронологии. Быстро (Postgres ILIKE, без LLM), голос ждать не должен.
  Включать функцию на голосовой карточке агента живьём перед звонком, как
  `agent_voice_context.apply_live_kb_functions` делает для функций базы знаний.
- **Когда искать** — в промпте звонка (подсказка для входящего с незнакомого
  номера): если клиент называет имя / компанию / говорит «мы только что
  переписывались», «я писал в WhatsApp» — сразу вызвать поиск и продолжить с
  места. Не допрашивать: одно «как вас зовут?» достаточно.
- **Починить `inbound_recent_contacts_hint`**: окно шире 1 часа (например, 48–72 ч,
  вынести в настройку), убрать ссылку на `search_contact_by_phone`, указать на
  новую функцию.
- **Клиент заранее предупредил** («позвоню с другого номера 0700…») — оркестратор
  в переписке записывает этот номер в карточку (см. задачу 3, второй номер), и
  входящий с него сразу узнаётся как знакомый, без поиска.
- Голосовой слой GPT-Live видит только первые `LIVE_VOICE_INSTRUCTIONS_MAX_CHARS`
  (6000) символов промпта — блоки контекста держать компактными.

### Готово, когда

- [ ] Клиент писал в WhatsApp вчера, звонит сегодня с другого номера, говорит «я
      Айбек, у меня стоматология» → агент находит его, обращается по имени и
      продолжает с того, о чём писали.
- [ ] Звонит с того же номера → узнаётся, как и раньше.
- [ ] Незнакомый, которого нет в базе → обычный разговор с новым клиентом, без
      ложных совпадений (при сомнении агент уточняет, а не угадывает).

## Задача 3. Склейка карточек одного клиента

### Как сейчас

Входящий с незнакомого номера на номер агента →
`AgentCallFinalizer._inbound_agent_call` создаёт НОВЫЙ `AgentContact` (status
`new`). Если это клиент, который писал с другого номера, у него две карточки,
история разделена, следующий разговор снова «с нуля».

### Что сделать

- **Второй номер в карточке.** Хранить дополнительные номера клиента (например,
  `memory["alt_phones"]` или отдельная колонка — решить; колонки добавлять в
  ранний старт `app.ensure_*`, как остальные). Поиск контакта по номеру
  (`inbound_known_contact_block`, `_inbound_agent_call`, `resolve_greeting`,
  `whatsapp_service.match_contact_by_phone` и т. п.) учитывает и их.
- **Склейка.** Когда на звонке или в переписке выяснилось, что это тот же человек
  (агент нашёл его функцией из задачи 2, или клиент сказал свой прежний номер),
  второй номер добавляется в основную карточку, а созданная лишняя карточка
  сливается в основную: звонки (`agent_calls`), задачи (`tasks`), треды
  мессенджеров (`agent_whatsapp_chats`, `agent_telegram_dialogs`, Instagram) —
  перепривязать; memory объединить; лишнюю карточку удалить. Сделать тулзой
  оркестратора (например `merge_contacts`) + автоматически в PostCall входящего
  звонка, если голосовой агент нашёл клиента.
- Склейка — необратимая операция: писать в лог, что с чем склеено, и сообщать
  владельцу одной строкой.

### Готово, когда

- [ ] После звонка с другого номера в CRM одна карточка клиента с обоими
      номерами и общей историей.
- [ ] Следующий звонок с любого из двух номеров — агент сразу узнаёт клиента.
- [ ] Ничего не теряется: звонки, записи, переписки, задачи на месте.
