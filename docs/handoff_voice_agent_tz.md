## 1. Итоговая цель («вау»)

Телефонный голосовой агент, который общается **как живой человек**: энергично, по делу,
логично, мгновенно понимает намерение, сам ведёт разговор к продаже/записи, помнит клиента.
Языки — **русский (чётко) и кыргызский (понятно, без акцента, без диалекта, без книжных
литературных слов, как носитель)**. От качества этого агента напрямую зависит доход владельца
и продажи платформы клиентам. Эталон — «вау, как будто говоришь с живым менеджером».

## 2. Архитектура голоса (что под капотом)

- Карточка ассистента — тип `eleven`, но движок голоса **`voice_engine = gpt_live`** (поле
  `eleven_assistant_configs.voice_engine` / у агента `eleven_voice_engine`). Это НЕ каскад
  ElevenLabs, а **OpenAI GPT-Live** речь-в-речь.
- **Голосовая модель: `gpt-live-1`** (full-duplex, слушает и говорит одновременно; сама решает,
  когда говорить; VAD-событий нет). Это топовая голосовая модель OpenAI — выше для нас нет.
- **Бэкенд делегирования (мозг рассуждений/функций): `gpt-5.6-luna`** (`LIVE_DELEGATION_MODEL`).
  Голос всё озвучивает сам; бэкенд подключается для поиска/функций/сложных рассуждений (≈пауза).
- Телефон: свой SIP-шлюз (Asterisk VPS `178.105.79.237`) → `/ws/sip/{call_id}` →
  `sip_media_adapter.py` (HandlerSocket) оборачивает тот же голосовой хендлер, что и виджет.
- **Два мозга в `backend/services/agent_prompts.py`:**
  - `ORCHESTRATOR_PROMPT_BASE` — центральный мозг (текст: CRM, планирование звонков, анализ,
    переписка в мессенджерах), сборка `build_orchestrator_prompt()`.
  - `VOICE_AGENT_PROMPT_BASE` — голосовой агент на звонке (получает задачу/стратегию от
    оркестратора в `custom_greeting`), сборка `build_voice_agent_prompt()`.
- **Промпт ЗВОНКА** собирается в `backend/services/agent_voice_context.py`
  (`build_call_system_prompt`) и подмешивается в `backend/api/sip_gateway.py` (входящие/исходящие)
  и `handler_eleven.py` (браузерный тест). Состав: инструкции агента → вопрос-ответ/секции →
  прайс каталога (с описаниями, где лежат номера) → материалы. Бюджет знаний 9000, лимит
  голосового слоя `LIVE_VOICE_INSTRUCTIONS_MAX_CHARS` = 16000.

### Ключевые файлы голоса
| Файл | Роль |
|---|---|
| `backend/websockets/live_client.py` | WS-клиент GPT-Live: `session.start`, `delegation.responses` (модель, инструменты, **пакет скорости**), подсказки голосового слоя `VOICE_DELEGATION_HINT` / `VOICE_TELEPHONY_HINT`, бэкенд-промпт `BACKEND_SYSTEM_PROMPT` |
| `backend/websockets/handler_live.py` | Сессия звонка: аудио, транскрипт, **пейсинг входящего аудио (token bucket)**, **автозавершение по прощанию+тишине**, функции |
| `backend/websockets/sip_media_adapter.py` | Мост SIP↔хендлер: аудио 8↔24кГц, перебивания, `call.hangup`, `_hangup_after_farewell` |
| `backend/services/agent_voice_context.py` | Сбор знаний в промпт звонка + живой пересчёт функций знаний |

| `backend/core/config.py` | Все env-настройки `LIVE_*` |

## 5. Env-переменные голоса (Render) — что добавили и зачем

Все с дефолтами в `backend/core/config.py`; пусто = значение по умолчанию модели.
| Переменная | Дефолт | Назначение |
|---|---|---|
| `LIVE_DELEGATION_MODEL` | `gpt-5.6-luna` | Бэкенд-модель рассуждений/функций. Следующий A/B: `gpt-6-luna` |
| `LIVE_VOICE_INSTRUCTIONS_MAX_CHARS` | `16000` | Сколько промпта видит голосовой слой (OpenAI лимит 16 384 токена) |

| `LIVE_DELEGATION_SERVICE_TIER` | `priority` | Fast mode, до 2.5× быстрее. Если OpenAI отклонит (`responses_validation_failed` в логе) — очистить |
| `LIVE_DELEGATION_REASONING_EFFORT` | `low` | Быстрее «думает» |
| `LIVE_DELEGATION_VERBOSITY` | `low` | Короче ответы бэкенда, меньше «воды» |
| `LIVE_DELEGATION_MAX_OUTPUT_TOKENS` | (пусто) | Потолок длины ответа бэкенда (≥16), пусто = без потолка |

оркестратора; железное правило «не говорить „не знаю“ без поиска в базе знаний».

## 9. Ограничения (ВАЖНО для обещаний клиентам)

- Русский и кыргызский для GPT-Live в документации OpenAI **не упомянуты вообще** — качество RU/KY
  знаем только по своим тестам. Обещать клиентам можно лишь то, что сами слышим на звонках.
- Голосов/акцентов для RU/KY нет; кастомные голоса — только «английские акценты».
- В GPT-Live НЕТ параметров VAD/порога тишины/скорости/эмоций — только промпт + наш код моста
  (перебивания, эхо, пейсинг). `turn_detection`/`semantic_vad` существуют лишь в Realtime API.
- Понимание кыргызской речи на `gpt-live-1` местами слабое (путает слова) — это ограничение
  модели. Если понадобится лучше — отдельный тест каскада ElevenLabs с Yandex/Google STT (не сейчас).

## 10. Как тестировать и читать лог

1. Render деплоит с `1710-voice-fix-2test` (деплой ~2 мин; мост пишет `backend_unavailable` — норма).
2. Владелец звонит на номер агента (вход `996705701707`), говорит по-русски и по-кыргызски,
   в конце прощается и молчит (проверка автосброса). Присылает «Лог звонка» (txt из «Диалоги»).
3. В логе смотреть:
   - `задержка ответа: средняя … максимальная …` — цель снизить (была 8.5 с / 11 с);
   - `responses_validation_failed` — если есть, пакет скорости отклонён → гасить соответствующую `LIVE_DELEGATION_*`;
   - `Автозавершение звонка` / `Прощание (…)` — работа автосброса;
   - `input_audio_rate_limit_exceeded` — не должно быть (чинили пейсингом);
   - повтор приветствия/прощания — не должно быть.

## 11. Правила работы (железобетонно)

- **Одна правка — один тестовый звонок (RU+KY) — лог — вывод.** Не валить несколько изменений
  разом: иначе непонятно, что помогло/сломало (на этом уже один раз обожглись, ветка `1610-voice-latency`).
- Каждая правка — отдельным коммитом с внятным «что меняем и чего ждём», чтобы легко откатить.
- Коммитим и пушим в текущую ветку; PR не создаём без прямой просьбы.
- Голос и виджет должны вести себя одинаково (общий хендлер).
- Приоритет владельца: КАЧЕСТВО и живость разговора (от этого его доход), скорость — следом.
