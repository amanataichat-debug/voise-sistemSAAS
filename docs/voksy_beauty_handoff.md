### Шаг 2.5 — кабинет клиента «Мои записи»

Цель: клиент без пароля видит свои записи в салоне и сам переносит, отменяет, повторяет визит.
- **Вход:** подписанная ссылка на клиента салона (как `/r/<токен>` и `/w/<токен>`: id карточки + HMAC на
  `JWT_SECRET_KEY` со своей солью), страница `/m/<токен>` (noindex). Вставка `{мои_записи}` в правилах
  автоматизаций (подтверждение, напоминания) и в «Вы записаны» на странице салона. Если владелец выберет и
  код — кнопка «Мои записи» на странице салона: телефон → код в мессенджер салона через очередь отправок →
  короткий токен клиента (только для `/api/client/*`). Аккаунт клиента по телефону для нескольких салонов
  (`client_accounts` из плана, раздел 2.7) — можно отложить: в 2.5 достаточно «одна ссылка = один салон».
- **Экран:**
  - ближайшие записи: дата, время, услуга(и), мастер, адрес, предоплата;
  - кнопки «Перенести» (выбор дня и времени — те же слоты, что на странице салона), «Отменить», «Повторить»;
  - история визитов: «Оставить отзыв» (ссылка `/r/`), «Записаться снова к <мастеру>»;
  - лист ожидания клиента: статус, «Больше не нужно»;
  - контакты салона, чат (`SalonChat`).
- **Правила:**
  - перенос и отмена — не позже `cancel_hours` из правил записи (`booking_service.change_too_late`); позже —
    «позвоните салону» и телефон;
  - запись источником `online`, журнал действий — клиент по имени;
  - владельцу в Telegram — «клиент перенёс / отменил»;
  - освободилось время — сработает лист ожидания (он уже сканирует сам).
- **API:** `/api/client/{token}` (GET — данные), `/slots`, `POST /bookings/{id}/reschedule|cancel`, `POST /repeat`;
  лимиты с IP; токен даёт доступ только к записям этой карточки в этом салоне.
- **Тест** `test_client_cabinet.py`: подделка токена, чужая запись — 404, правило `cancel_hours`, перенос в занятое
  время, визит из нескольких услуг. Плюс снимки iPhone и документация (CLAUDE.md, план, handoff).

### Шаг 2.6 — голос

Цель: голосовой агент салона на звонке переносит и отменяет записи, сам звонит подтвердить визит и пригласить
на повтор. Перед любой правкой голоса — `docs/voice_live_standard.md`, после — `python scripts/voice_tests/test_voice_standard.py` и
`python scripts/voice_regression.py`.
- **Перенос и отмена на звонке:** голосовые функции рядом с `find_booking_slots` / `book_appointment`
  (`functions/booking_voice.py`): «мои записи», перенос, отмена. Клиент — по номеру звонящего (`sip_calls`).
  Действие — только после «да» клиента. Те же правила `cancel_hours`. Включаются в памяти перед звонком, как
  `apply_live_booking_functions`.
- **Звонок-подтверждение:** новое правило автоматизаций `confirm_call` (канал — звонок):
  - накануне в окно звонков;
  - только номера O!, пустой кошелёк — пропуск с причиной в журнале отправок;
  - постановка звонка через существующую исходящую очередь (`SipGatewayService.queue_outbound_call`) с
    контекстом записи;
  - итог разговора (подтвердил / перенёс / отменил / не ответил) → статус записи и строка в журнале действий;
  - не ответил — до N попыток, потом сообщение в мессенджер.
- **Приглашение на повтор звонком:** у правила «пора повторить» канал «звонок», если мессенджера нет, а номер на O!
  (у ИИ-управляющего это уже есть — не дублировать: `manager_covers`).
- **Тест** без сети и БД (функции, правила, тексты) + PostgreSQL (очередь звонков, итоги, лимиты, кошелёк).
