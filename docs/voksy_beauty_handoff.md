## 4. Как продолжить в новой сессии

1. Убедиться, что у аккаунта Claude есть доступ к репозиторию `amanataichat-debug/voise-sistemSAAS`
   (GitHub подключён в claude.ai, приложение Claude установлено на репозиторий).
2. Открыть новую сессию Claude Code на этом репозитории, ветка **`2511-beauty`** (последний коммит — см. `git log origin/2511-beauty`).
3. Первое сообщение — готовый текст в разделе 6 ниже.
4. Окружение для тестов и снимков (так работали в прошлой сессии):
   - зависимости: сначала `pip install --ignore-installed setuptools wheel markupsafe`, потом
     `pip install -r requirements.txt pyflakes`;
   - PostgreSQL 16 (`/usr/lib/postgresql/16/bin`): `initdb` в `/var/tmp/pgdata` (владелец postgres),
     запуск `pg_ctl -D /var/tmp/pgdata -o '-k /var/tmp' -l /var/tmp/pg.log start`, база `voksy_test` +
     `create extension btree_gist`;
   - полная проверка: `CHECK_DATABASE_URL="postgresql://postgres@localhost:5432/voksy_test?host=/var/tmp" bash scripts/check_all.sh`
     (тестовая база очищается; `test_mobile_app.py` уже входит в регрессию);
   - снимки (Playwright, iPhone 13 + компьютер 1360×900): `uvicorn app:app` на пустой базе падает на alembic
     «Multiple head revisions», поэтому приложение для снимков запускаем без startup-хуков: свой скрипт, который
     ставит `DATABASE_URL` на отдельную базу (`voksy_shots`), импортирует `app`, делает
     `app.app.router.on_startup.clear()` и `uvicorn.run(app.app, port=8765)`; базу перед этим заполняет
     скрипт-«посев» (Base.metadata.create_all + `app.ensure_booking_tables()` + `ensure_user_profile_columns()` +
     салон, мастера, услуги, клиенты, записи). Токен владельца кладём в `localStorage.auth_token`,
     `sessionStorage.vf_shell_seen=1`. Проверяем: ширина документа = ширине экрана, нет ошибок в консоли.

Решения владельца по этапу 3 (27.11.2026, план — разделы 9 и 12): порядок **касса → долги → зарплата → склад**;
касса — **смены администраторов**; выручка — **по оплатам** (визит без оплаты — долг клиента, зарплата мастера —
от оплаченных визитов); схемы зарплаты — **свой % по категориям** и **ставка за смену** (вместе с прежними % + оклад).
Принцип прежний: **Beauty Pro = Profi один в один**, кому и когда писать решает агент по инструкции владельца.

### Сделано: 3.1 «Касса и оплата визита»

по оплатам с первой смены салона. Подробно — CLAUDE.md, абзац Voksy Beauty, «Шаг 3.1». Снимки iPhone и компьютера
проверены (ширина = экрану, ошибок нет).

**Проверить на живом салоне:** открыть смену, принять оплату визита наличными и картой, закрыть смену с пересчётом;
у салона, который кассой ещё не пользовался, «Финансы» показывают выручку по визитам, пока не открыта первая смена.

### ТЗ шага 3.2 «Долги и отчёт дня» (вопросы закрыты, можно начинать)

Решения владельца 27.11.2026: отчёт дня — всем Beauty-тарифам, **время выбирает владелец** (по умолчанию 21:00);
напоминание о долге — **только вручную** (клиенты обычно платят сразу); списать долг — **только владелец**.

- **Долг** = визит «пришёл / завершён» с ценой, оплаченный не полностью (`cashbox.paid_by_booking`), только после
  `cash_start` салона (до кассы долгов нет); визит из нескольких услуг — один долг.
- **Где видно:** вкладка «Долги» на экране «Касса» (кто, за что, сколько, с какого дня, «Принять оплату»,
  «Напомнить», «Списать»); плитка «Долги клиентов» на главной салона; в карточке клиента (`salon_clients.client_card`) —
  «Долг N сом» и «Принять оплату»; в «Моих записях» клиента — строка «к оплате N сом» (оплаты онлайн нет).
- **«Напомнить о долге»** — кнопка: одно сообщение клиенту в его мессенджер через очередь отправок (`idem_key` по визиту
  и дню — не чаще раза в день), текст RU/KY по языку клиента. Автоматической рассылки нет.
- **«Списать долг»** — только владелец (сотруднику 403), с причиной; запись в журнал действий; визит перестаёт быть
  долгом; выручкой не считается.
- **Отчёт дня** — Telegram-бот агента и push, раз в день в выбранное время (переключатель и время — на экране «Касса»,
  один раз за день на всех воркерах — `claim_agent_job`): выручка по способам, смены и расхождения, новые долги,
  неявки, возвраты. Те же цифры — карточка «Итог дня» на экране «Касса».
- **Голос и чат владельца:** «кто должен?», «сколько сегодня в кассе?» — быстрые функции / инструменты.
- Тест `scripts/voice_tests/test_debts.py` (PostgreSQL), снимки iPhone и компьютера, документы.
