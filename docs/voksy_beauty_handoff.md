### Не проверено на живых данных (проверить при первой возможности)

1. Чат на сайте с **настоящим ботом и кредитами** (в тестах ответ бота подставлен заглушкой).
2. Push-уведомления на **реальном телефоне** (Android — в браузере; iPhone — только у установленного приложения).
   Ключи VAPID: лучше задать в Render `VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY`, иначе создаются в базе сами.
3. Сценарии ИИ-управляющего на **живых клиентах** (письма и звонки в 10:00–20:00, режим «на одобрение»).
4. Задеплоена ли ветка `2511-beauty` на Render — уточнить (Render деплоит ту ветку, к которой привязан).

5. Главная салона и журнал на **живом салоне**: «Предложить клиентам» (подбор давних клиентов мастера), загрузка
   мастеров при сменах 2/2 (сейчас график — по дням недели), «сообщения без ответа» при большом инбоксе.
6. Приложение не стартует локально через `uvicorn app:app` на пустой базе: alembic «Multiple head revisions»
   (не связано с Beauty; на Render старт идёт своей веткой). Для снимков запускали приложение без startup-хуков.

## 2а. Этап 2 «Клиенты возвращаются» — по шагам

Решения владельца (26.11.2026): в карточке клиента обязательны **только имя и телефон**; отзывы **4–5 — сразу,
1–3 — после проверки владельцем**; лист ожидания — **автоматически первому** (30 мин на ответ, потом следующему);
порядок: 2.1 карточка → 2.2 очередь отправок и автоматизации → 2.3 отзывы → 2.4 лист ожидания → 2.5 кабинет
клиента → 2.6 голос.

Не проверено на живом салоне (2.2): реальная отправка в WhatsApp/Telegram/Instagram из очереди (в тестах отправка

включится «Подтверждение записи» (по умолчанию вкл.) — первое сообщение клиенту, которого записал администратор.

Шаг 2.3 проверен: тест на PostgreSQL (бот и ссылка, 4–5 / 1–3, один отзыв на визит, ответ салона и очередь, скрыть /
показать, рейтинг только по опубликованным, «Показать ещё», отзывы мастера, JSON-LD, выключатель «на странице», права,
главная, кабинет мастера, перенос старых оценок); снимки iPhone 13 и компьютера (страница салона: рейтинг под названием,
раздел «Отзывы», карточка и окно мастера; «Оцените визит»: звёзды, текст, «спасибо», 1–3; кабинет «Отзывы»: ждут
проверки, окно ответа, «на странице»; кабинет мастера): ширина страницы = ширине экрана, ошибок в консоли нет.
Попутно: «спасибо» у визита из нескольких услуг уходило по одному на каждую услугу — теперь одно, после последней.

Не проверено на живом салоне (2.3): как Google покажет звёзды (разметка `aggregateRating` валидна, но для отзывов о
себе Google может не рисовать звёзды в выдаче); превью ссылки `/r/<токен>` в WhatsApp (заголовок с названием салона
есть, картинки нет). Просьба оценить по умолчанию выключена (галочка «Просить оценку» в «Спасибо после визита») —
владельцу стоит включить её на экране «Автоматизации», иначе отзывы будут приходить только от ИИ-управляющего (Beauty Pro).

Шаг 2.4 проверен: тест на PostgreSQL (очередь «первому», 30 минут → следующему, «не подходит» → это окно больше не
предлагаем, время суток, запись по ссылке и ботом с проверкой «да», окно заняли, «больше не нужно», срок прошёл, нет
мессенджера, кабинет, страница салона, права); снимки iPhone 13 и компьютера (экран «Лист ожидания», окно «В лист
ожидания», кнопка с числом ждущих в журнале, страница «Освободилось время», шаг «Лист ожидания» на странице салона и
«Вы в листе ожидания»): ширина страницы = ширине экрана, ошибок в консоли нет.

Не проверено на живом салоне (2.4): реальная доставка предложения (в тестах очередь отправок не отправляет), как клиенты
отвечают «да» в WhatsApp без бота (без бота «да» в переписке никто не обработает — остаётся ссылка в сообщении), окно
не держится за клиентом 30 минут (его может занять запись по ссылке) — если владельцу важно держать, нужен «блок на 30
минут» (решение владельца). Сообщения уходят только с 8:00 до 20:30 по Бишкеку — ночью освободившееся окно предложим утром.

Не проверено на живом салоне: клиенты салона, у которого ещё нет бота, — записи без бота не заводят карточку CRM
(так было и до 2.1), поэтому такие клиенты в «Клиентах» не появятся, пока бот не создан.

## 4. Как продолжить с другого аккаунта

1. Убедиться, что у рабочего аккаунта Claude есть доступ к репозиторию `amanataichat-debug/voise-sistemSAAS`
   (GitHub подключён в claude.ai, приложение Claude установлено на репозиторий).
2. Открыть новую сессию Claude Code на этом репозитории, ветка **`2511-beauty`**.
3. Первое сообщение, например:
   > Прочитай docs/voksy_beauty_handoff.md, CLAUDE.md (абзац Voksy Beauty) и docs/voksy_beauty_plan.md.
   > Работаем в ветке 2511-beauty. Начинаем этап 2 «Клиенты возвращаются» — сначала задай мне вопросы
   > из раздела «Следующий шаг», потом делай.
4. Для тестов на базе в новой среде: поставить зависимости (`pip install -r requirements.txt`), поднять
   PostgreSQL, создать пустую базу и запустить `CHECK_DATABASE_URL=postgresql://… bash scripts/check_all.sh`
   (тестовая база очищается).
5. Коммиты — только в `2511-beauty`, без pull request, пока владелец не попросит.
