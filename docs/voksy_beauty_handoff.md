### 2.1 Журнал действий (кто что сделал)

Зачем: владелец видит, кто перенёс или отменил запись, кто поменял цену, что сделал бот — и может разобраться
в спорной ситуации с мастером или клиентом.

- **База:** таблица `activity_log` (план, раздел 3): кто (владелец / сотрудник / мастер / ИИ / клиент /
  система + имя), действие, объект (запись, услуга, мастер, клиент, страница, тариф, расход…), было → стало
  (JSON с изменёнными полями), IP, время. Хранить 180 дней. Только добавление, без правки.
- **Где писать** (одна функция, например `services/activity.py → log(...)`, вызывается из сервисов, а не из
  страниц, чтобы ловить все входы — кабинет, сотрудник, мастер, бот, звонок, ссылка, чат на сайте):
  запись (создана, перенесена, растянута, статус, отменена, предоплата получена), блоки времени,
  услуги и цены, мастера (график, цены, оплата), страница салона и чат, сотрудники и права,
  расходы и зарплаты, решения по ИИ-управляющему (одобрил / отклонил), вход админа в кабинет клиента
  (уже есть `admin_audit_log` — показать в том же списке).
- **API:** `GET /api/beauty/activity` — фильтры: кто, что, объект, период; постранично. Видят владелец и
  роль «Управляющий»; мастер — нет.
- **Экран:** лента с фильтрами (сегодня / неделя / всё; люди; вид действия), строка «Айгуль перенесла
  запись Нурай: ср 11:00 → чт 15:00 · 14:32». В карточке записи — вкладка «История» этой записи.
- **Тест:** `test_activity.py` на PostgreSQL — каждый вход пишет строку с правильным «кто», мастер журнал
  не видит, старые строки чистятся.

### 2.2 Главная салона (дашборд для салонов)

Сейчас у салонов на главной уже есть карточки «Сегодня», «Месяц», «Популярные услуги», «Мастера»,
«Записи на сегодня» и утренний отчёт ИИ-управляющего (`static/js/dashboard-home.js`). Шаг 1.7 —
собрать из этого **одну рабочую главную салона**, телефон в первую очередь:

1. **Сейчас и сегодня:** кто сейчас в салоне (статус «пришёл»), следующие записи с временем и мастером,
   пришли / впереди / не пришли, выручка за день.
2. **Требует внимания:** записи без подтверждения на завтра, ждём предоплату, ждут одобрения ИИ-управляющего,
   новые записи от бота / страницы / чата с последнего захода, клиенты с оценкой 1–3, сообщения без ответа.
3. **Свободные окна сегодня и завтра** по мастерам + кнопка «Предложить клиентам» (через ИИ-управляющего,
   с одобрением).
4. **Загрузка мастеров** на сегодня и неделю.
5. **Последние действия** — 5 строк из журнала действий + «Весь журнал».
6. Быстрые кнопки: «Записать», «Заблокировать время», «Расход».

Каждый блок — только из настоящих данных (никаких демо). Тест: блоки на PostgreSQL + снимки на iPhone (Playwright).

## 4. Как продолжить с другого аккаунта

1. Убедиться, что у рабочего аккаунта Claude есть доступ к репозиторию `amanataichat-debug/voise-sistemSAAS`
   (GitHub подключён в claude.ai, приложение Claude установлено на репозиторий).
2. Открыть новую сессию Claude Code на этом репозитории, ветка **`2511-beauty`**.
3. Первое сообщение, например:
   > Прочитай docs/voksy_beauty_handoff.md, CLAUDE.md (абзац Voksy Beauty) и docs/voksy_beauty_plan.md.
   > Работаем в ветке 2511-beauty. Продолжаем шаг 1.7 «Главная салона и журнал действий» — сначала
   > задай мне вопросы из раздела «Вопросы владельцу перед 1.7», потом делай.
4. Для тестов на базе в новой среде: поставить зависимости (`pip install -r requirements.txt`), поднять
   PostgreSQL, создать пустую базу и запустить `CHECK_DATABASE_URL=postgresql://… bash scripts/check_all.sh`
   (тестовая база очищается).
5. Коммиты — только в `2511-beauty`, без pull request, пока владелец не попросит.
