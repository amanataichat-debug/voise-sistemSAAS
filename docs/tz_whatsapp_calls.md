# ТЗ: звонки WhatsApp для голосового агента (свой шлюз)

Составлено 28.11.2026. Новая ветка от `2511-beauty` (имя задаёт владелец).
Работаем, коммитим и пушим только в неё. Pull request не создаём.

## Коротко для владельца

Агент научится **принимать звонки в WhatsApp и сам звонить клиентам через
WhatsApp**: на любой номер, где есть WhatsApp, не только на O!.
Делаем свой «переходник» на отдельном маленьком сервере на основе готовой
бесплатной программы с GitHub. Он передаёт голос между WhatsApp и нашим агентом,
как сейчас Asterisk передаёт голос оператора O!. Основная система только
дополняется: телефония, переписка, кабинет и бот не меняются, по умолчанию всё
выключено.

Этапы: **1 — проба** на запасном номере (агент берёт трубку и разговаривает, сам
звонит) → **2 — надёжность и кабинет** (подключение по QR, перезвон из переписки,
«Диалоги», кошелёк) → **3 — открыть клиентам**.

От владельца: запасной телефон с WhatsApp, маленький сервер Hetzner (~4–5 €/мес),
QR-код и тестовые звонки.

---

## 1. Зачем

- Исходящие звонки агента сейчас только на номера O! (`check_phone_operator`,
  `queue_outbound_call`). Клиенты с других операторов пишут в WhatsApp, и
  позвонить им агент не может.
- Звонок WhatsApp идёт широкой полосой (16 кГц и выше) вместо телефонных 8 кГц,
  поэтому распознавание речи, особенно кыргызской, должно быть заметно лучше.
- За минуты оператору не платим.

## 2. Выбор решения

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Свой шлюз: whatsmeow + meowcaller** (выбран) | бесплатно; звонки и голос не уходят третьей стороне; входящие и исходящие, PCM в обе стороны | неофициальный протокол; при изменениях WhatsApp ждём обновления библиотеки; библиотеке ~полгода |
| Green API (запасной вариант) | готовый сервис, поддержка 24/7 | 690–1 982 руб/мес за номер или партнёрский тариф; голос и записи у российского провайдера; WebRTC на нашей стороне; исходящие только тем, кто писал или звонил за 72 ч |
| WhatsApp Business Calling API (Meta) | официально, без риска бана | нужен одобренный WABA, плата Meta, SIP в Asterisk; отдельный большой проект |

Библиотеки:
- https://github.com/purpshell/meowcaller — Go, MIT. Входящие и исходящие,
  аудио на кодеке MLow, `Source` (наш звук) и `Sink` (звук собеседника, `[]float32`).
  Не готово: запасной кодек Opus для старых клиентов.
- https://github.com/tulir/whatsmeow — Go, MPL 2.0. Вход по QR (связанное
  устройство), хранение сессии.

Лицензии разрешают коммерческое использование. Сохраняем файлы LICENSE и авторство.

**Если этап 1 провалится** (звук не идёт, звонки рвутся, кодек не поддержан у
части клиентов) — меняем только шлюз на Green API. Бэкенд (раздел 5) остаётся
тем же: протокол шлюз↔бэкенд не зависит от того, кто держит звонок.

## 3. Архитектура

```
Клиент в WhatsApp
   │  (протокол WhatsApp VoIP, MLow)
   ▼
wa-call-gateway  (новый VPS, Go: whatsmeow + meowcaller)
   │  исходящие WebSocket, как у SIP-моста:
   │   • управляющий  wss://voksyai.online/ws/wa-call-gateway/control
   │   • звук звонка  wss://voksyai.online/ws/sip/{call_id}   (PCM16 16 кГц)
   ▼
Бэкенд (Render): HandlerSocket (sip_media_adapter.py) → тот же хендлер карточки
(SIP_HANDLERS["eleven"]: Voksy Voice / GPT-Live / Gemini Live)
   → функции, CallTranscript, call_logs, eleven_conversations, кошелёк, PostCall
```

Принцип из CLAUDE.md: **телефония и виджет ведут себя одинаково**. Звонок WhatsApp —
третий вход в тех же агентов, без своей логики разговора.

### 3.1 Где живёт шлюз

- **Отдельный VPS** Hetzner CX22/CX23 (`wa-call-1`), а не `wa-gateway-1` с
  Evolution и не SIP-сервер: падение или нагрузка шлюза звонков не задевает
  переписку и телефонию.
- Всё в `infra/wa-call-gateway/`, обновление только через `install.sh` с GitHub,
  как у двух других серверов. Руками на сервере ничего не правим.
- Все соединения с сервера исходящие: входящие порты не нужны, кроме SSH.
  Медиа WhatsApp идёт через релеи WhatsApp (UDP наружу).

### 3.2 Один номер — два связанных устройства

Номер агента уже подключён к Evolution для переписки. Шлюз звонков — ещё одно
связанное устройство того же номера (WhatsApp допускает до 4). Шлюз **только
работает со звонками**: сообщения он не читает и не отправляет, переписка
остаётся в Evolution. Это проверить на этапе 1 (п. 4.5).

## 4. Этап 1 — проба (цель: живой разговор с агентом)

### 4.1 Шлюз `infra/wa-call-gateway/gateway/` (Go)

- Один процесс, несколько аккаунтов (на пробе один). Сессии whatsmeow — в SQLite
  в `/opt/voksy-wa-call/data` (права 600, в бэкапах Hetzner).
- Вход по QR: шлюз отдаёт QR бэкенду по управляющему сокету (`qr` event), бэкенд
  показывает его в кабинете. На этапе 1 допускается QR в консоли
  (`journalctl`) / ASCII.
- **Входящий звонок:** `OnIncomingCall` → `call.event started` в управляющий
  сокет (номер или LID звонящего, имя из профиля) → бэкенд отвечает `accept`
  с `assistant_id` или `reject` (номер не привязан / кошелёк пуст / агент выключен)
  → `call.Answer()` → открыть медиа-сокет `/ws/sip/{call_id}`.
- **Исходящий:** команда `originate {call_id, account_id, to}` → `client.Call(ctx, "+996…")`
  → события `ringing` / `answered` / `failed {reason}` → медиа-сокет после ответа.
- **Звук:** Sink (`[]float32`, частота meowcaller) → ресемплинг в PCM16 LE 16 кГц моно,
  кадры 20 мс (640 байт) → бэкенд. От бэкенда — PCM16 16 кГц любыми кусками →
  очередь с темпом реального времени → Source. Поддержать `clear` (сброс очереди
  при перебивании), `hangup`, `mark` (эхо, когда проигрывание дошло) — как
  `bridge.py`, чтобы адаптер работал без изменений.
- Тишина, когда бэкенд молчит (не обрывать поток к WhatsApp).
- Сторож: звонок длиннее `MAX_CALL_SECONDS` (по умолчанию 3600) кладётся.
- Переподключение управляющего сокета с паузой 1→30 с; на время деплоя Render
  (1–2 мин `backend_unavailable`) входящие отклоняются, а не висят.
- Логи в journald, без содержимого разговора.
- Конфиг `/etc/voksy-wa-call/gateway.env`: `GATEWAY_ID=wa-call-1`,
  `GATEWAY_TOKEN` (= `WA_CALL_GATEWAY_TOKEN` в Render), `BACKEND_WS_URL`.

### 4.2 Протокол (тот же, что у SIP-моста, + поля WhatsApp)

Медиа-сокет `/ws/sip/{call_id}` — без изменений, кроме `start`:
```json
{"type":"start","call_id":"…","channel":"whatsapp","direction":"inbound",
 "caller":"996555123456","caller_jid":"…@s.whatsapp.net","caller_name":"Айбек",
 "account_id":"…","assistant_id":"…","assistant_type":"eleven",
 "format":{"encoding":"pcm16","sample_rate":16000,"channels":1,"frame_ms":20}}
```
Управляющий сокет — отдельный путь `/ws/wa-call-gateway/control`
(токен `WA_CALL_GATEWAY_TOKEN`), чтобы не смешивать с выбором SIP-шлюза для
исходящих O!. События: `hello`, `account.state` (`qr`, `connected`,
`logged_out`, `banned`), `call.event` (`started|ringing|answered|ended|failed`),
`pong`. Команды: `accept`, `reject`, `originate`, `hangup`, `login`, `logout`, `ping`.

### 4.3 Бэкенд — минимум для пробы

- `backend/api/wa_call_gateway.py`: управляющий сокет, состояние шлюзов в воркере
  (как `GATEWAYS` в `sip_gateway.py`), решение `accept`/`reject` по привязке
  аккаунта к агенту и по кошельку (`WalletMeter` / пустой кошелёк → `reject`).
- Звонок записывается в `sip_calls` с `call_metadata.channel = "whatsapp"`
  (новых таблиц для звонков не заводим: журнал, «Диалоги», запись, PostCall,
  стенограмма уже на них).
- `sip_media_adapter.HandlerSocket`: профиль `whatsapp` — вход 16 кГц, **без**
  телефонной обработки 8 кГц (`PhoneVoice` high-pass/−3 дБ, G.711 у GPT-Live,
  АРУ Gemini — включать только если покажет запись), выход ресемплится в 16 кГц.
  Эхо-ворота (`echo_gate.py`) оставить: громкая связь на телефоне есть и в WhatsApp.
- `/ws/sip/{call_id}` принимает `sample_rate` 16000 из `start` (сейчас ждёт 8000).
- Выключатель `WA_CALLS_ENABLED` (по умолчанию `0`) и список разрешённых
  владельцев `WA_CALLS_USERS` (id через запятую) на время пробы.
- Привязка на пробе: одна строка-аккаунт → агент владельца (раздел 5.1),
  заводится скриптом `scripts/wa_call_account.py` в Render Shell.

### 4.4 Проверки этапа 1 (вместе с владельцем)

1. Звонок с другого телефона в WhatsApp тестового номера → агент отвечает
   приветствием, понимает русский и кыргызский, отвечает без задержек.
2. Перебивание: заговорили поверх агента — он замолкает (`clear` работает).
3. Агент кладёт трубку после прощания (`hangup_call`).
4. Исходящий: команда со скрипта → телефон звонит в WhatsApp → разговор.
5. Звонок виден в «Диалогах» с репликами и «Логами звонка»; PostCall разобрал.
6. Переписка Evolution на этом же номере продолжает работать во время звонка.
7. Звонок, когда трубку берёт ещё и сам телефон (`accepted_elsewhere`): кто
   выигрывает и что видит шлюз — записать.
8. Звонящий со старым клиентом WhatsApp (если найдём): работает ли без Opus.
9. Деплой Render посреди звонка: звонок падает аккуратно, шлюз
   переподключается сам.

Итог этапа — короткий отчёт: задержка ответа, качество звука на слух, что не
работает. Решение «дальше своё или Green API» принимает владелец.

## 5. Этап 2 — надёжность и кабинет

### 5.1 Данные

Таблица `agent_wa_call_accounts` (`app.ensure_wa_call_tables()`, аддитивно):
`id`, `user_id`, `agent_config_id`, `gateway_id`, `phone` (E.164 без плюса),
`status` (`pending_qr|connected|logged_out|banned|error`), `last_error`,
`inbound_enabled` (принимать звонки), `outbound_enabled` (звонить самому),
`daily_outbound_limit` (по умолчанию 20), `first_phrase` (необязательно),
`created_at`, `connected_at`. Сессия whatsmeow — только на шлюзе, не в базе.

### 5.2 Кабинет

- В каналах агента (Старт `start-bot.html`, Profi — коннекторы `agent.html`)
  строка «Звонки WhatsApp»: подключить по QR (окно с опросом статуса, как
  `whatsapp-account.js` / вход Telegram по QR), состояние, переключатели
  «Принимать звонки» и «Звонить клиентам», отключить.
- Честное предупреждение при подключении: неофициальный способ, есть риск
  блокировки номера WhatsApp, лучше отдельный номер.
- Все тексты — белый лейбл: никаких названий библиотек и провайдеров.

### 5.3 Агент звонит через WhatsApp

- `queue_outbound_call` / `trigger_immediate_call` / задачи `channel="call"`:
  если номер клиента не O!, но у агента есть подключённый аккаунт звонков
  WhatsApp с `outbound_enabled` и у клиента есть WhatsApp → звонок через WhatsApp.
  Номер O! → как раньше через SIP (оператор надёжнее). Порядок решает код, не модель.
- `check_phone_operator` / `agent_can_call_contact` учитывают звонок WhatsApp:
  в разборе переписки «ты МОЖЕШЬ сам позвонить», и правило «ЗВОНОК КЛИЕНТУ» в
  `chat_sales_rule` перестаёт отправлять таких клиентов звонить на наш номер.
- Все защиты звонков работают как есть: окно звонков, «один звонок в день»,
  `MAX_CALLS_PER_DAY`, недозвон, пауза, «не звонить», `is_platform_number`
  (не звонить самому себе).
- Лимиты против бана: `daily_outbound_limit`, не больше N звонков в час, не звонить
  тем, кто ни разу не писал и не звонил (первым — только по ответу на переписку).
  Цифры подобрать на этапе 1–2, начать осторожно.

### 5.4 Входящие

- Номер WhatsApp агента = входящая линия агента: тот же `inbound_first_phrase`,
  `find_client` / `inbound_known_contact_block` (клиент узнаётся по номеру — у
  WhatsApp он есть всегда, кроме LID: тогда по имени профиля и через переписку
  Evolution с тем же JID).
- Звонок вне окна / агент выключен / кошелёк пуст → `reject`, владельцу в Telegram
  «пропущенный звонок WhatsApp от …».

### 5.5 Деньги, журнал, запись

- Кошелёк: минута как у входящего звонка движка карточки (без надбавки оператора
  `WALLET_OPERATOR_OUT_SOM_PER_MIN` — оператора нет). `wallet_transactions.channel = "whatsapp"`.
- «Логи звонка»: первая строка «Звонок WhatsApp», события шлюза (`ringing`,
  `accepted_elsewhere`, причина конца), качество звука («Путь звука» адаптера).
- Запись: шлюз сводит обе стороны в WAV → MP3 → тот же
  `POST /api/sip/recordings/{call_id}` (`X-Gateway-Token`) → R2 → `recording_url`.
- «Диалоги», карточка клиента, инбокс (лента звонков), аналитика: канал
  «WhatsApp-звонок» (`sip_calls.call_metadata.channel`), отдельный цвет
  проверить валидатором палитры.

### 5.6 Надёжность шлюза

- Номер вышел из устройства / заблокирован → `account.state` → статус в кабинете
  + сообщение владельцу в Telegram; исходящие через этот аккаунт отключаются.
- Несколько аккаунтов на одном шлюзе; предел одновременных звонков на шлюз
  (`max_calls`, начать с 10), сверх — `reject` входящего / исходящий ждёт.
- Обновление библиотек — только через `install.sh` после проверки на тестовом номере.

## 6. Этап 3 — открыть клиентам

- Тарифы: Старт и Profi (как WhatsApp-переписка); на Старте — только входящие
  (исходящий звонок — инициатива, `INITIATIVE_TOOLS`), Profi — всё.
- Выключатель `WA_CALLS_ENABLED=1`, `WA_CALLS_USERS` пусто = всем.
- Лендинг и FAQ — после месяца стабильной работы у нас, нашими словами («Звонки
  WhatsApp»), с упоминанием риска блокировки в документах.
- Документация: `infra/wa-call-gateway/claude-wa-call-gateway.md`, `SERVER.md`,
  строка в `claude-index.md` и CLAUDE.md (раздел серверов: третий сервер).

## 7. Что НЕ трогаем

- SIP-шлюз (`infra/sip-gateway/`), Asterisk, исходящие на O!.
- Evolution API и WhatsApp-переписку (`whatsapp_service.py`, `whatsapp_inbound.py`).
- Промпты голоса (слой платформы GPT-Live — `docs/voice_live_standard.md`):
  звонок WhatsApp получает ровно тот же промпт, что телефонный.
- Voximplant — мёртвый код.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Блокировка номера WhatsApp | тестовый номер на пробе; лимиты исходящих; первыми звоним только тем, кто писал; предупреждение клиентам |
| WhatsApp поменял протокол — звонки не работают | шлюз отдельно, остальное живёт; следим за обновлениями meowcaller; запасной вариант — Green API с тем же бэкендом |
| Клиент без кодека MLow (старое приложение) | фиксируем в журнале причину; ждём Opus в библиотеке |
| Одновременно звонит и телефон владельца номера | проверить на этапе 1; рекомендовать отдельный номер для агента |
| Сессии WhatsApp на сервере — доступ к номеру | сервер только с SSH-ключом, файлы 600, токен шлюза только в env |
