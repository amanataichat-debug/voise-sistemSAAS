# Передача: голосовой агент GPT-Live, что узнали за 16–17.10.2026

Ветка `1710-voice-clean` = `1610-kb-calls` (`ec1af2c`) + только документация. Код звонка здесь **такой, каким был до всех правок**.
Старая рабочая ветка `1610-voice-latency` не удалена: из неё можно переносить отдельные куски (список ниже).

## Почему начали заново
После деплоя ветки `1610-voice-latency` владелец услышал, что звонок стал хуже: агент хуже понимает, «логика пропала», голоса звучат хуже. Одновременно менялось сразу много вещей:
код (запас звука, подсказки модели, лимит промпта), **промпт агента** (длинный → новый короткий про воронку), **голос** (`marin` → `gleam`), переменные в Render (`LIVE_VOICE_PROMPT_EXTRAS=lean`).
Какая из них виновата, неизвестно. Правило для новой ветки: **одно изменение за раз, после каждого — звонок и лог.**

## Порядок проверки (предлагается)
1. Задеплоить чистую ветку, в карточке агента вернуть **старый промпт и голос `marin`**, в Render убрать лишние переменные (`LIVE_VOICE_PROMPT_EXTRAS`, `SIP_*`, `LIVE_*`, кроме `LIVE_DELEGATION_MODEL`). Сделать 2 звонка (рус + кыргызский). Это эталон «как было хорошо».
2. Менять по одному: сначала только промпт → звонок → лог; потом только голос; потом код.

## Факты из логов (звонки 16–17.10)
- Задержка ответа с `lean`: средняя 2,4 с (без функции 2,2, с функцией 2,9).
- Разрывы звука при запасе 200 мс: 58 за 224 с речи.
- Выходной поток GPT-Live **непрерывный** (в паузах тишина), поэтому «ассистент говорит» нельзя определять по приходу `session.output_audio.delta`, только по громкости.
- Модель сама почти не вызывает `hangup_call`: линия висела после прощания.
- Модель на кыргызском выдала мусор «Google Günüñüz boloşun!» в прощании.
- В вызове голос был `gleam` (по документации — североамериканский английский стиль): возможная причина акцента.
- У агента был один товар в каталоге: поэтому называл только «SIM за 600 сом».
