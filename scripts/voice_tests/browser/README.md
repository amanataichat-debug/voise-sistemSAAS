# Проверки голосового окна в настоящем браузере

Python-тесты (`scripts/voice_tests/*.py`) проверяют бэкенд. Здесь — то, что видно и слышно только
в браузере: отчёт-инфографика и эхо-ворота микрофона. Оба раза, когда владелец жаловался на голос
(«блоки не загораются», «пингует на каждом слове»), причина была именно тут.

Нужен Node с Playwright и Chromium (в контейнере разработки они уже есть).

```bash
python3 scripts/voice_tests/browser/serve.py 8753 &
node scripts/voice_tests/browser/check.js    # карточки, сцены отчёта под речь, демо-сокет
node scripts/voice_tests/browser/gate.js     # эхо-ворота микрофона
```

Стенд (`harness.html`) грузит НАСТОЯЩИЙ `/static/agent/voice-chat.js`, подменяя только сокет
(`window.__push(d)` шлёт событие, как сервер) и микрофон (тишина вместо getUserMedia).

- `check.js` — карточки дашборда, сцены отчёта загораются по порядку под речь агента
  (данные — `report.sample.json`, снято с `owner_voice_demo.get_report`), агент молчит → блоки
  показываются сами, демо-режим идёт в `/ws/demo-voice`. Скриншоты — в `$VOICE_SHOTS` или во временную папку.
- `gate.js` — `VoksyVoice.__gate(rms, агент_говорит, время)`: эхо динамика глохнет, щелчок не
  перебивает, речь открывает ворота с четвёртого кадра, громкая связь поднимает порог, новая
  реплика перемеряет уровень эха.

Если звук опять рвётся на живом разговоре — в консоли окна `VoksyVoice.stats()`:
уровень эха, открыты ли ворота, сколько раз обрывали ответ, запас буфера и число разрывов.
