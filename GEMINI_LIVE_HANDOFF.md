# ТЗ: доведение Gemini Live 3.8 на платформе Voksy AI

## Контекст
Ветка разработки и деплоя: **`2710-start-tier`**. Коммитить и пушить только туда, PR не создавать.
Перед деплоем ЛЮБОЙ правки голоса: `python scripts/voice_regression.py`.
Проверки движка Gemini: `scripts/voice_tests/test_gemini_live_engine.py` (идут без сети и БД).

Gemini Live 3.8 — **третий движок «Модели голоса» карточки ElevenLabs и агента обзвона**
(`voice_engine="gemini_live"`, рядом с `eleven` и `gpt_live`). Серверный ключ `GEMINI_API_KEY`
(задан в Render, работает). Основные файлы:
- `backend/websockets/gemini_client.py` — клиент Google Live (setup, подключение, схемы функций, долгие звонки)
- `backend/websockets/handler_gemini_live.py` — сессия карточки (диалог/журнал/кошелёк/webhook)
- `backend/websockets/handler_gemini.py` — разбор событий Google (общий с Gemini-ассистентами)
- `backend/websockets/voice_hints.py` — подсказки манеры/языка/функций для Gemini
- `backend/websockets/call_guard.py` — завершение звонка после прощания + защита hangup_call
- `backend/api/sip_gateway.py` — SIP-роут (подмешивание знаний, профиль адаптера `gemini`, гарантия карточки диалога)

## Что уже сделано (ветка 2710-start-tier, все коммиты запушены)
1. Тестовая ветка `0111-gemini-test` влита в `2710-start-tier`.
2. Долгие звонки: `sessionResumption` + `contextWindowCompression`, переподключение без повторного приветствия (`GEMINI_LONG_CALLS=0` — выключатель).
3. Язык: правило как в промпте звонков (держись языка приветствия), приоритет инструкции агента над общими подсказками.
4. Стенограмма звонка идёт потоком `transcript.delta` → PostCall (уведомление владельцу, память, хронология).
5. Завершение звонка после прощания + защита `hangup_call` (паритет с GPT-Live).
6. Схемы функций чистятся под Gemini (`gemini_schema`) — у `hangup_call` было поле `examples`, Google отвергал весь setup.
7. **ГЛАВНОЕ:** заголовки websocket — `extra_headers` → `additional_headers` для `websockets>=14` (Render/Python 3.14). Это была причина «молчит и сбрасывает через 3 с»: соединение падало на открытии. GPT-Live работал, у него fallback уже был.
8. Диагностика в «Диалогах»: любой несостоявшийся eleven-звонок оставляет карточку диалога с причиной от Google + журнал (`_record_failed_dialog`, `_ensure_eleven_dialog_row`).

## Как проверять (первый шаг новой сессии)
1. Убедиться, что ветка `2710-start-tier` задеплоена на Render.
2. Владелец звонит на номер +996 705 701 707, привязанный к агенту «Анри», движок карточки — Gemini Live.
3. Открыть «Диалоги» → карточка этого звонка → «Логи звонка» → «Скачать .txt».
4. В журнале теперь есть:
   - «Движок голоса карточки … : gemini_live» (подтверждает, что звонок реально шёл на Gemini);
   - при сбое — «⚠ Звонок не соединился … <причина от Google>» или «Google не принял настройку сессии …»;
   - «События Gemini за звонок: …» (что прислал Google), ошибка если нет расшифровки речи клиента.
5. Прислать этот .txt в новую сессию — по нему чинить дальше по факту, а не по догадкам.
6. Если нужно проверить ключ/модель напрямую: Render Shell → `python scripts/test_gemini_live.py`
   (проверяет ключ, список доступных Live-моделей, setup по нарастающей, звук в ответ).

## Вероятные открытые проблемы (решать ТОЛЬКО по логу живого звонка)
- **Модель.** `gemini-3.8-live` может быть недоступна на этом ключе/эндпоинте (v1beta BidiGenerateContent).
  Если лог покажет «model not found» — сменить `GEMINI_LIVE_MODEL` в Render на доступную Live-модель
  (список даст `scripts/test_gemini_live.py`).
- **Язык/кыргызский.** Качество речи на кыргызском и переключение языка оцениваются только на слух.
- **Эмоции/живость.** В 3.8 affective dialog удалён из API — управляется только текстом промпта (`voice_hints.py`).
- **Распознавание речи клиента.** `GEMINI_INPUT_TRANSCRIPTION_LANGUAGES` теперь по умолчанию `ru,ky` (см. ниже).

## Переменные окружения Gemini (Render)
- `GEMINI_API_KEY` — серверный ключ (задан).
- `GEMINI_LIVE_MODEL` — `gemini-3.8-live` (менять, если модель недоступна).
- `GEMINI_LONG_CALLS` — `1`/`0` (возобновление сессии + сжатие контекста).
- `GEMINI_INPUT_TRANSCRIPTION_LANGUAGES` — по умолчанию `ru,ky`, `none` — выкл.
- `GEMINI_THINKING_LEVEL` — `low`/`medium`/`high`, только при `GEMINI_LIVE_MODEL=gemini-3.8-live-extended-thinking`.
- `GEMINI_VAD_PROFILE` / `GEMINI_VAD_SILENCE_MS` — детектор речи (по умолчанию `fast` / `800`).
- `VOICE_COST_USD_PER_MIN_GEMINI_LIVE` — себестоимость минуты (default 0.03$).

## Принцип работы (важно для новой сессии)
- Gemini у карточки ElevenLabs = GPT-Live по интеграции: один и тот же промпт карточки, знания,
  память, CRM, уведомления, кошелёк, «Диалоги». Отличается только транспорт (Google вместо OpenAI).
- Правило: что умеет GPT-Live на звонке — должно уметь и Gemini. При любой новой правке голоса
  проверять, что она одинакова для обоих движков.
- Полное описание движка — в `CLAUDE.md`, блок «Движок Google Gemini Live».
