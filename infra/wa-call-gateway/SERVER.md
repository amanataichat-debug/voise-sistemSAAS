## Что это за сервер

| Параметр | Значение |
|---|---|
| Роль | Принимает и делает звонки WhatsApp номера агента и передаёт голос нашему агенту |
| Хостинг | Hetzner Cloud, CX22/CX23 (~4–5 €/мес), Ubuntu 24.04 |
| Имя / IP | `wa-call-1`, **`2.31.204.51`** (Hetzner CX23, Falkenstein; создан 28.11.2026) |
| Вход | `ssh root@2.31.204.51` — только SSH-ключом владельца с Mac (пароля нет) |
| Что установлено | Одна программа `voksy-wa-call` (Go, наш код + бесплатные библиотеки с GitHub) |
| Входящие порты | Только SSH. Все соединения сервер открывает сам (к WhatsApp и к Render) |
| Кто ставит и обновляет | Скрипт `install.sh` из этой папки. Руками на сервере ничего не правим |

Это **третий сервер** (не путать):
1. SIP-шлюз `178.105.79.237` — звонки оператора O! (`infra/sip-gateway/`).
2. WhatsApp-шлюз переписки `wa-gateway-1`, `91.99.124.169` — Evolution (`infra/whatsapp-gateway/`).
3. **Этот** — звонки WhatsApp. Падение одного не задевает остальные.

Схема:

```
Клиент звонит в WhatsApp → серверы WhatsApp → [wa-call-1]
     voksy-wa-call (связанное устройство номера агента, звук MLow 16 кГц)
        ├─ управление:  wss://voksyai.online/ws/wa-call-gateway/control
        └─ голос:       wss://voksyai.online/ws/sip/{call_id}   (PCM16 16 кГц)
                └─ тот же агент, что отвечает по телефону и в виджете
```

Номер агента остаётся подключённым к Evolution для переписки; шлюз звонков — **ещё одно
связанное устройство** того же номера (WhatsApp разрешает до 4). Шлюз переписку не читает и
не отправляет.

> **Факт 28.11.2026:** шлюз стоит на своём сервере `wa-call-1` (`2.31.204.51`), а не на `wa-gateway-1` —
> на `wa-gateway-1` для пробы не подошло (сброс пароля root). Раздел ниже — исходный план, оставлен для истории.

## Проба на существующем сервере (исходный план, не используется)

На время пробы шлюз ставится на уже работающий **WhatsApp-шлюз переписки `wa-gateway-1`**
(`91.99.124.169`, CX23: 2 ядра, 4 ГБ — запаса хватает). Шлюз звонков — отдельная программа со
своим systemd-сервисом и своими папками; Evolution в Docker он не трогает, портов не открывает.
`install.sh` сам видит, что сервер общий, и **файрвол не меняет**. Откат — одна команда
`uninstall.sh` (ниже), Evolution продолжает работать. После удачной пробы можно переехать на свой
сервер: та же команда установки на новом VPS.

SIP-сервер `178.105.79.237` для пробы не берём: там живые звонки оператора O!.

## Установка (этап 1, проба)

Нужно: **запасной** телефон с WhatsApp (не основной номер — есть риск блокировки, способ
неофициальный), сервер Hetzner.

1. Создать сервер в Hetzner: CX22 или CX23, Ubuntu 24.04, ваш SSH-ключ, имя `wa-call-1`.
2. Подключиться к нему (PowerShell на компьютере): `ssh root@<IP сервера>`.
3. На сервере одной командой:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/amanataichat-debug/voise-sistemSAAS/2811-wa-calls/infra/wa-call-gateway/install.sh | bash
   ```
   В конце скрипт напечатает `WA_CALL_GATEWAY_TOKEN` — его нужно поставить в Render.

### Шаг А: эхо-тест (без бэкенда, проверяем только звук WhatsApp)

```bash
curl -fsSL https://raw.githubusercontent.com/amanataichat-debug/voise-sistemSAAS/2811-wa-calls/infra/wa-call-gateway/install.sh | VOKSY_ECHO_TEST=1 bash
journalctl -u voksy-wa-call -f
```
В журнале появится QR-код. На запасном телефоне: WhatsApp → ⋮ → **Связанные устройства** →
**Привязать устройство** → отсканировать. Позвонить на этот номер в WhatsApp с другого
телефона — шлюз возьмёт трубку и будет повторять ваш голос. Так видно, что звук идёт в обе
стороны и какая у него задержка.

Выключить эхо-тест: та же команда с `VOKSY_ECHO_TEST=0`. Привязка номера сохранится, но
связать его с агентом всё равно нужно через шаг Б (у эхо-теста свой служебный аккаунт —
отвязать его: WhatsApp → Связанные устройства → «Voksy AI» → Выйти).

### Шаг Б: звонок с агентом

1. **Render → Environment**: `WA_CALL_GATEWAY_TOKEN` = токен из конца установки,
   `WA_CALLS_ENABLED=1`, `WA_CALLS_USERS=<id владельца>` (через запятую). Render сам перезапустится.
2. **Render → Shell** (номер привязывается к агенту и показывает QR прямо там):
   ```bash
   python scripts/wa_call_account.py create --agent <id агента>
   ```
   QR появится в Shell (и в журнале шлюза). Отсканировать так же, как в шаге А.
3. Позвонить на этот номер в WhatsApp — ответит агент.
4. Исходящий (проба): включить и позвонить:
   ```bash
   python scripts/wa_call_account.py set <id аккаунта> --outbound on
   python scripts/wa_call_account.py call <id аккаунта> 996555123456 --any
   ```
   `--any` — только для пробы: звонить и тем, кто ни разу не писал агенту (обычно первым
   звоним только тем, кто сам писал или звонил).
5. Звонки видны в «Диалогах» (с журналом звонка и записью) и в
   `python scripts/wa_call_account.py calls`.

## Откат (удалить шлюз звонков с сервера)

```bash
curl -fsSL https://raw.githubusercontent.com/amanataichat-debug/voise-sistemSAAS/2811-wa-calls/infra/wa-call-gateway/uninstall.sh | bash
```
Удаляются только сервис `voksy-wa-call` и его папки. В Render — `WA_CALLS_ENABLED=0`.

## Обновление

С Mac: Терминал → `ssh root@2.31.204.51` → та же команда установки. Секреты (`/etc/voksy-wa-call/gateway.env`) и привязка номера
(`/opt/voksy-wa-call/data`) сохраняются. Во время перезапуска идущие звонки кладутся.
Обновлять библиотеки — только после проверки на тестовом номере.

## Что смотреть

| Команда (на сервере) | Что показывает |
|---|---|
| `journalctl -u voksy-wa-call -f` | Журнал: QR, входящие, кто положил трубку, ошибки |
| `systemctl status voksy-wa-call` | Работает ли программа |
| `curl -s 127.0.0.1:9095/health` | Связь с бэкендом, аккаунты и их состояние, идущие звонки |
| `cat /etc/voksy-wa-call/gateway.env` | Настройки (токен — секрет, не пересылать) |

Частые ситуации:
- **QR истёк** → в Render Shell: `python scripts/wa_call_account.py qr <id>`.
- **В журнале `logged_out`** → номер отвязали на телефоне. Новый QR — та же команда.
- **`banned`** → WhatsApp временно заблокировал номер. Звонки через WhatsApp остановлены,
  владельцу пришло сообщение в Telegram. Ждать срок блокировки, уменьшить исходящие.
- **Звоните на номер, а шлюз молчит (в журнале нет `incoming WhatsApp call`)** → возможно,
  WhatsApp не доставляет звонки устройству не «в сети». Переустановить с `VOKSY_SEND_PRESENCE=1`
  (минус: пока шлюз «в сети», на телефоне этого номера нет push-уведомлений) и записать результат в отчёт.
- **`control socket down … retry`** на 1–2 минуты → деплой Render, это нормально; входящие в
  это время отклоняются, а не висят в гудках.

## Безопасность

- Сессия WhatsApp (доступ к номеру!) — только на этом сервере: `/opt/voksy-wa-call/data`,
  права 700/600, в бэкапах Hetzner. Сервер — только по SSH-ключу.
- Токен шлюза — только в `gateway.env` (600) и в Render.
- В журнал пишутся события, без содержимого разговоров; номера — со скрытыми цифрами.
